# DoodhDirect API Specification

Base URL:

`/api/v1`

## 1. API Standards

### Authentication
`Authorization: Bearer <access_token>`

### Correlation
`X-Correlation-Id` optional from client, generated by API when absent.

### Idempotency
Required for financial/duplicate-sensitive POST requests:
`Idempotency-Key: <uuid>`

### Pagination
Query:
`page=1&pageSize=25`

### Standard success response

```json
{
  "success": true,
  "data": {},
  "message": null,
  "errors": []
}
```

### Standard error

```json
{
  "success": false,
  "data": null,
  "message": "Human readable message",
  "errors": [
    {
      "code": "BUSINESS_RULE",
      "field": null,
      "message": "Complaint window has expired."
    }
  ]
}
```

## 6. Order APIs

### Create order
`POST /orders`

Request:

```json
{
  "addressId": "uuid",
  "orderType": "ONE_TIME",
  "items": [
    {
      "productId": "uuid",
      "quantity": 1.5
    }
  ],
  "couponCode": null,
  "walletAmount": 0,
  "paymentMethod": "RAZORPAY_UPI"
}
```

Server performs:
- Address ownership validation
- Product availability
- Branch allocation
- Quantity validation
- Price calculation
- Coupon validation
- Wallet validation
- Payment initiation

### Other order APIs

`GET /orders`

`GET /orders/{orderId}`

`POST /orders/{orderId}/cancel`

`POST /orders/{orderId}/test-request`

`POST /orders/{orderId}/complaints`

## 17. Common HTTP Status Codes

200 — success
201 — created
202 — accepted/asynchronous
400 — validation error
401 — unauthenticated
403 — forbidden
404 — not found
409 — conflict/idempotency/state conflict
422 — business validation
429 — rate limited
500 — unexpected server error
503 — dependency unavailable

---

## 18. API Authorization Rule

Every endpoint must have one of:

- Public
- Authenticated customer
- Authenticated employee
- Role/permission specific
- Owner/global admin

Never infer authorization from client UI visibility.
